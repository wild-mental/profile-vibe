# Partner Profiles

비즈니스 파트너·고객별로 **맞춤 프로필 버전**을 제작·관리하는 작업 경로입니다.

`app/` 아래의 풀 버전 프로필 페이지 개발과는 **별개 트랙**입니다. 여기서는 특정 파트너의 포맷·업무 방향에 맞춰, 기존 이력 콘텐츠를 `profile-sum` 가이드라인으로 압축·재정렬한 산출물을 다룹니다.

## 제작 입력 3축

각 파트너 프로필은 아래 세 가지를 함께 두고 작성합니다.

| # | 입력 | 역할 |
|---|------|------|
| 1 | **파트너 브리프** | 포맷 요구, 업무·포지셔닝 방향, 배경 자료, 커뮤니케이션 히스토리 |
| 2 | **기존 프로필 원천** | 이미 작성해 둔 여러 프로필 버전의 구체 문서 내용 (`source-docs/`, 풀 페이지 카피, 과거 산출물 등) |
| 3 | **`profile-sum` 스킬** | Alignment · Evidence · Fidelity 기준의 간결하고 체계적인 Leadership Card 작성 가이드 |

```
파트너 브리프 + 기존 프로필 원천
        ↓  profile-sum
맞춤 프로필 산출물 (md / HTML / 파트너 지정 포맷)
```

## 디렉터리 규약

파트너(또는 고객)당 하나의 폴더를 둡니다. 슬러그는 영문 kebab-case를 권장합니다.

```
partner-profiles/
├── README.md                 ← 이 문서
├── _template/                ← 신규 파트너 착수 시 복사
│   ├── brief.md              ← 포맷·방향·커뮤니케이션 히스토리
│   ├── sources.md            ← 참조할 기존 프로필/문서 목록
│   └── output/               ← profile-sum 산출물
└── <partner-slug>/           ← 예: acme-corp, hana-fintech
    ├── brief.md
    ├── sources.md
    └── output/
        └── profile.md        ← (또는 .html 등 요청 포맷)
```

신규 착수 예시:

```bash
cp -R partner-profiles/_template partner-profiles/<partner-slug>
```

### 선택 문서 (파트너가 양식을 지정한 경우)

파트너가 **자체 제출 양식**(pptx·docx 등)을 주거나 배경 맥락이 복잡할 때는 아래를 추가한다. `EMERITUS/`가 이 확장 구성의 참조 사례다.

| 파일 | 언제 필요한가 |
|------|---------------|
| `README.md` | 폴더 인덱스·상태판·차단 이슈 — 문서가 3개를 넘어가면 |
| `template-spec.md` | 파트너 지정 양식이 있을 때. 필드 인벤토리·분량 예산·작성 규칙을 **원본 파일에서 역공학**해 고정 |
| `content-map.md` | 양식 필드 ↔ 보유 이력 자산 매핑 + 초안 후보. 각 항목에 원천 근거를 붙여 Fidelity를 강제 |
| `outbound-email.md` | 프로필이 이메일에 동봉될 때. 이메일의 주장과 프로필의 증거가 어긋나지 않게 정합 표를 둔다 |

## 작업 흐름 (요약)

1. `_template`를 복사해 `<partner-slug>/`를 만든다.
2. `brief.md`에 파트너 포맷·방향·커뮤니케이션 히스토리를 채운다.
3. `sources.md`에 참조할 기존 프로필/문서 경로를 적는다.
4. `profile-sum`으로 방향성에 정렬된 카드를 생성하고 `output/`에 저장한다.
5. 파트너 피드백이 오면 `brief.md`에 히스토리를 남기고 `output/`을 갱신한다.

## 범위 경계

| 이 경로에서 함 | 이 경로에서 하지 않음 |
|----------------|----------------------|
| 파트너·고객별 맞춤 프로필 버전 제작·보관 | `app/` 풀 버전 포트폴리오 페이지의 UI/기능 개발 |
| 브리프·원천·산출물의 버전 추적 | 공용 디자인 시스템·배포 파이프라인 변경 |

풀 페이지 본체는 `app/`, 원본 이력 문서는 `source-docs/`를 각각 단일 소스로 두고, 이 경로는 **파트너향 파생본만** 관리합니다.
